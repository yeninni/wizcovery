# WIZCOVERY

GitHub Pages에서 바로 실행하는 회원 구매 분석·굿즈 탐색·매장 지도·위즈픽업·스마트 탐색 프로토타입입니다.

- 사이트: https://yeninni.github.io/wizcovery/
- 시간·데이터 실험실: https://yeninni.github.io/wizcovery/simulator.html

## 조건 검색의 선수 명단

조건 검색은 2026년 11월 14일 공개 명단의 선수 77명과 군보류 선수 13명을 제공합니다. 육성선수 12명이 포함되어 있으며 투수, 포수, 내야수, 외야수, 군보류 그룹으로 나뉩니다. 선택 목록과 문장 검색, 선수 개체와 등번호는 모두 `player-roster.js`를 사용합니다. 외국인 선수는 등록명과 별칭으로 검색할 수 있습니다.

모든 선수에 홈과 어웨이 마킹지 예시를 연결했습니다. 이름이나 조건으로 검색하면 공통 유니폼 사진과 선수별 마킹지, 등번호, 합계 가격, 재고, 마킹 경로를 함께 보여줍니다. 마킹지는 각 20,000원, 재고 5개인 시연용 가정이며 실제 판매 목록은 아닙니다. 업로드한 장성우 마킹키트는 별도 상품으로 유지하고, 기존 강백호 시연 상품은 현재 조건 검색에서 제외합니다. 명단 출처, 기준일과 이용 조건은 [선수 명단 문서](data/player-roster.md)에 정리했습니다.

## 업로드된 실제 회원 자료

‘데이터셋’을 열면 업로드한 엑셀의 **구매회원 분석**이 먼저 표시됩니다. 2017·2018·2019·2022·2023·2024·2025년 구매회원 340,910개 관측을 3,931개 집단으로, 회원 구성 664,023개 관측을 982개 집단으로 가공했습니다. 연도·성별·연령대·지역 필터, 구매빈도 분포, 연도별 차트, 집단별 표와 엑셀·CSV 다운로드를 제공합니다.

원본의 1행을 1회원 관측으로 집계했습니다. 연도 간 회원 ID가 없어 누적 관측 수는 고유 인원수와 다릅니다. 2020·2021년 자료는 없고, 지역 공란은 미상으로 유지합니다. 기준 연도가 없는 회원 구성 자료는 별도 탭에서 조회합니다. 상세 출처·정의·검증 결과는 [회원 집계 데이터 문서](data/README.md)에 있습니다.

회원 자료는 데이터셋을 열 때 불러옵니다. 상품·매장 시뮬레이션의 시간·상황 설정은 실제 회원 집계에 영향을 주지 않습니다. 회원 필터와 차트·요약은 실제 집계값을 코드로 계산하며, LLM 기능은 아직 연결하지 않았습니다.

## 서버 없이 돌아가는 합성 데이터

Python·Node·외부 호스팅 없이, `browser-simulator.js`가 한국 시간과 요일에 따라 값을 계산합니다. 정적 파일을 게시하면 됩니다. 실제 매장·재고·경기 일정·주문과 연결하지 않습니다.

- 월요일 가상 비경기일, 화~금 18:30·토~일 14:00 가상 경기
- 경기 전/후 수요, 주말 가중치로 재고·인원·대기시간 계산
- 5초마다 재계산하며 조회 횟수 때문에 재고가 추가로 줄어들지 않음
- 인기 95 품절, 혼잡, 16시 재입고 시나리오
- 경기 1시간 전 외부 마킹 접수 마감, 대기+작업시간 표시
- 가상 시각에 맞춰 픽업 슬롯과 30분 준비시간 적용
- 영업 종료에는 상품을 판매 불가로 표시하고 보유 재고는 별도 유지
- 굿즈 탐색·지도·스마트 탐색·픽업이 같은 브라우저의 설정과 생성값 사용

저장된 설정이 없는 첫 방문은 한국 달력 기준 가까운 토요일(당일 포함) 오전 11시의 ‘영업 중’ 상태로 시작합니다. 사용자가 선택한 영업 종료·현재 시각 등의 설정은 유지됩니다.

개발용 `simulator.html`에서는 임의 시각·시드와 시간 재생을 사용할 수 있습니다. 각 화면 오른쪽 아래에는 작은 ‘데이터셋’과 ‘데이터 설정’ 버튼이 있습니다. ‘데이터 설정’에서 기준 시각과 상황을 바꿀 수 있습니다. 설정은 가능하면 localStorage에 저장하고, 저장이 차단되면 해당 페이지 메모리에만 유지합니다. 새 시드·날짜·시나리오는 새 가정으로 전체 상태를 재계산합니다.

## 발표 시연에서 데이터 확인하기

‘데이터 설정’ 바로 위의 **데이터셋** 버튼을 누르면 실제 회원 집계와 상품·매장 시연 데이터를 출처별로 열 수 있습니다. 열람과 다운로드는 상품의 설정·재고·선택한 사이즈를 변경하지 않습니다.

- **구매회원 분석**: 기본 2025년 집계에서 시작합니다. 연도·성별·연령대·지역을 선택하면 평균 구매횟수, 2회 이상 구매 비중, 구매빈도·연도별 차트와 집단별 표가 함께 바뀝니다.
- **회원 구성**: 기준 연도가 없는 전체 회원 구성을 성별·연령대·지역으로 조회합니다. 연도별 구매율로 해석하지 않습니다.
- **상품 재고**: 전체 29종, 사진 상품 18종, 관계 시연용 상품 11종을 검색하고 사이즈별 개점·보유·판매 가능 재고를 확인합니다.
- **매장 서비스**: 영업 상태, 인원·대기시간, 외부 마킹, 구역별 혼잡도, 픽업 시간대를 확인합니다.
- **온톨로지**: 검색에 쓰는 개체 ID와 관계를 확인합니다. ‘호환 마킹지’로 거르면 `product:4 → compatibleWith → kit:choi-home` 연결을 보여줄 수 있습니다.
- **원본 JSON / JSON 내려받기**: `fan_data`에 회원 집계를, `catalog`·`ontology`·`simulation`에 상품·매장 시연값을 담습니다. `meta.sources`로 출처를 구분합니다. 화면 미리보기는 회원 표 각각 앞 20개만 표시하고 위의 JSON 버튼으로 전체 집계를 내려받습니다. 사이즈별 재고의 기준은 `simulation.inventory`이며, 관계 모델에 고정한 예시 마킹지 재고는 `demo_stock`입니다.

발표에서는 데이터셋의 ‘구매회원 분석’에서 **2025년 · 여성 · 20대 · 경기도 수원시**를 선택하면 구매회원 관측 1,615건, 구매횟수 합계 7,381회를 확인할 수 있습니다. 상품 품절 시연은 ‘데이터 설정 → 인기 95 품절’을 선택한 뒤 ‘상품 재고’ 탭에서 ‘어센틱 95’를 검색합니다. 별도 [데이터 모니터](https://yeninni.github.io/wizcovery/simulator.html)에서는 시간 재생과 시드 변경까지 확인할 수 있습니다.

**다른 사용자 간 주문/재고 공유, 실제 결제·예약·알림 전송은 없습니다.** 동일한 시각·시드·시나리오에는 같은 결과가 나오지만 각 브라우저의 선택은 독립적입니다. 가상 주문은 새로고침하면 사라집니다.

## 온톨로지와 JSON-LD

상품, 선수, 마킹지, 등번호, 매장 구역, 서비스, 디자인, 큐레이션 태그, 사이즈별 SKU를 하나의 그래프로 다룹니다. 조건 검색은 이 그래프를 그대로 쓰고, 같은 그래프를 표준 JSON-LD 문서로 내보낼 수 있습니다.

- `ontology/schema.jsonld`: 어휘 문서입니다. `schema.org`, `rdfs`, `owl`, `wiz` 접두사와 클래스 10개, 객체 속성 10개를 선언하고, SHACL 형태 9개로 필수 값과 값의 형을 적어 둡니다.
- `ontology/graph.jsonld`: `node tools/export-jsonld.cjs`로 만드는 현재 그래프입니다. 표준 JSON-LD 처리기로 확장하면 3,482개 트리플이 되고, 사이트를 띄우지 않고도 읽을 수 있습니다.
- `WizKnowledge.toJsonLd()`: 브라우저에서 같은 문서를 메모리에서 만듭니다. `@context`는 어휘에서 만들고, 관계는 IRI 참조로, 값은 선언된 xsd 형으로 직렬화합니다.
- `WizKnowledge.validateOntology()`: 어휘의 도메인과 레인지, 끊긴 참조, SHACL 형태(최소 개수, 클래스, 형, 최솟값)를 확인하고 리포트를 돌려줍니다. 형태로 적기 어려운 모순은 별도 규칙으로 검사합니다. 보관 처리한 상품이 현역 선수와 이어지는 경우와 마킹지에 적힌 등번호가 선수 등번호와 다른 경우입니다.

현재 그래프는 위반 0건, 경고 27건입니다. 경고는 공개 명단에 등번호가 없는 군보류 선수의 마킹지 26건과, 명단에 없는 선수 이름을 참조하는 보관 상품 1건입니다. 검증 코드와 리포트 구조는 [온톨로지 문서](ontology/README.md)에 정리했습니다.

`ontology.js`는 브라우저에서 바로 실행되는 스크립트라 어휘를 파일로 읽지 않고 내장합니다. `ontology/schema.jsonld`를 고친 뒤에는 `node tools/sync-ontology-schema.cjs`로 사본을 맞추고 `node tools/export-jsonld.cjs`로 그래프 문서를 다시 만듭니다. 두 파일이 어긋나면 단위 테스트가 알려줍니다.

## 개발

저장소 루트에서 일반 정적 파일 서버로 열 수 있습니다. 서버 프로그램은 개발 편의용이며 배포 환경에는 필요하지 않습니다.

```bash
python3 -m http.server 8000
```

`index.html`, `store-map.html`, `pickup.html`, `smart.html`, `simulator.html`을 확인합니다. 기존 체크아웃에서 작업하면 되며 별도 Git worktree는 필요하지 않습니다.

- `player-roster.js`: 기준일과 출처가 있는 선수 명단 및 이름 검색
- `catalog.js`: 상품과 큐레이션 예시
- `browser-simulator.js`: 브라우저 내 합성 데이터 엔진과 설정
- `live-demo.js`: 공통 시각/상황 컨트롤, 5초 갱신
- `fan-data.js` / `data/`: 실제 회원 집계 조회·필터·차트·다운로드
- `dataset-viewer.js`: 현재 적용 데이터의 읽기 전용 표·관계 조회·JSON 내보내기
- `simulator-dashboard.js`: 서버 없는 데이터 실험실
- `ontology.js`: 관계 기반 상품 검색, JSON-LD 직렬화, 온톨로지 검증
- `experience.js`: 사이즈 가이드·가상 알림·마킹 안내

## 화면 구성과 길 안내

화면 구조는 HTML, 공통 스타일은 `ui.css`, 각 화면의 동작은 `goods.js` / `store-map.js` / `pickup.js` / `smart.js`로 분리되어 있습니다. `product-art.js`는 상품 사진과 표시용 상품명을 공유합니다. 홈페이지에는 `assets/products/`의 업로드 사진 18종을 표시하며, 원본 연결 정보는 해당 폴더의 README에 정리했습니다. UI 폰트는 `assets/fonts/Pretendard-Black.otf`이며 `typography.css`에서 버튼·입력·SVG 텍스트까지 적용합니다.

캐릭터의 ‘왕복 1회’ 안내는 목적지에서 입구로 복귀한 뒤 종료합니다. 동작 줄이기 설정에서는 자동 재생을 멈추지만, 사용자가 직접 시작·다시 안내를 누르면 해당 경로를 걸어서 안내합니다. 캐릭터 상세 화면의 걷기 미리보기도 직접 켤 수 있습니다. 다시 걷는 동작은 ‘다시 안내’ 또는 재시작 버튼을 눌러야 시작됩니다. 모바일에서는 지도 옆 시작 버튼이 경로를 직접 실행하며 화면 밖의 하단 버튼을 대신 누르지 않습니다. 하단에서 안내를 시작하면 지도와 캐릭터가 보이는 위치로 돌아옵니다. Playwright와 Chromium이 있는 개발 환경에서는 다음 회귀 검증을 실행할 수 있습니다.

```bash
node --test tests/*.test.cjs tests/*.browser.cjs
```
